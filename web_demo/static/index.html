01 / WHY

Agent 越运行，
上下文和能力越容易失控。

全量 Skill 持续占用输入；动态内容破坏 Prompt 前缀；子 Agent 的工具与路径边界容易扩散；未经验证的成功经验还可能把一次偶然做法固化为长期偏见。

01 无关 Skill 消耗 Token 02 动态前缀扰动 KV Cache 03 子 Agent 权限逐层扩张 04 错误经验长期污染决策

02 / DESIGN

三条约束，构成一套长期运行机制。

01

Context Efficiency

稳定内容靠前，动态信息靠后。

会话开始宽召回候选 Skill，前三轮累计选择后固化工作集；稳定 Skill 进入 System Prefix，Memory 与临时 Skill 只在当前轮进入 Sidecar。既保住必要能力可见性，也避免 100 个 Skill 每轮全量输入。

01 · STABLESystem Prefix身份 · 协议 · 权限 · 工作集
02 · APPENDConversation对话 · 工具结果 · 压缩摘要
03 · EPHEMERALSidecarMemory · 临时 Skill · RAG
02

Least Privilege

权限不是 Prompt 描述，而是运行时事实。

将“工具、路径、读写模式”绑定成不可拆分的权限原子。子 Agent 创建时只能申请父节点可完整覆盖的子集；调用前裁剪可见工具，执行前再把真实参数转成请求原子复核。

root read / repo
agent-a read / src
agent-b git / inspect
request write / secrets
DENIED
03

Evolution Governance

只从证据中学习，也允许遗忘。

成功任务沉淀为具体 Memory 与可迁移 Skill；新经验先进入验证期，通过正确性与 Token 收益 A/B 后生效。生效后若在召回场景累计造成错误，则退役并停止自动召回。

03 / EVIDENCE

不是只少放内容，
而是保住需要的内容。

对照组在每轮 System Prompt 中加载全部 100 个 Skill；实验组通过场景工作集和 Sidecar 按需加载。统计包含查询扩展与重排等额外模型调用。

样本为 3 类 19 轮连续会话，轮次并非独立样本；19/19 是该工程测试内的观察结果，不宣称泛化为 100% 召回保证。
